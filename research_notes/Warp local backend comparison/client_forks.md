# Warp client forks and local-agent implementations

## Which projects truly run agent inference without Warp services, and where is that implemented?

### Takeaway
All three inspected forks have a real client-side inference path rather than merely relabeling Warp BYOK: `man-brain/warp` calls OpenAI-compatible Chat Completions through a small neutral engine; Zap dispatches every agent turn to a configured provider through `genai`; Loom intercepts locally owned model IDs before the inherited Warp-server path. Their account and cloud isolation strategies differ substantially: man-brain uses upstream `skip_login` plus a hard Warp-API deny gate, Zap replaces authentication with an always-local facade, while Loom retains hosted support but makes local/BYOK/CLI paths usable from a logged-out GUI.

### Cited Findings
- **Recency checked 2026-10-03:** the inspected heads were man-brain `2f7576e` (committed 2026-09-10), Zap `8954864` (2026-09-28), and Loom `8d7e9d7` (2026-09-19). Thus all are recent forks relative to our checkout's 2026-09-30 base, although recency alone does not establish production maturity. — [man-brain head](https://github.com/man-brain/warp/commit/2f7576e71081118939fbd4c66aa38fd25277eecd); [Zap head](https://github.com/zerx-lab/zap/commit/8954864e335187aecb2b2319050adc8c4da256df); [Loom head](https://github.com/rustcor-foundry/loom/commit/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9)

#### man-brain/warp
- The fork's `local_agent` crate is independent of Warp protobuf types. It defines a provider-neutral transcript, JSON-schema tool definitions, streamed text/reasoning/tool/usage events, and one-turn `run_turn`; the host is responsible for executing emitted tools and submitting a follow-up request with results. — [local_agent/src/lib.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/local_agent/src/lib.rs)
- Its engine POSTs directly to an OpenAI-compatible `/chat/completions`, applies bearer auth, consumes SSE, accumulates fragmented tool calls, and treats dropping the returned stream as cancellation. It recognizes `reasoning_content`, `reasoning`, and `reasoning_text`, covering common DeepSeek/llama.cpp-style variants. — [engine.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/local_agent/src/engine.rs); [openai.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/local_agent/src/openai.rs)
- `local_route.rs` resolves the selected model against `settings.custom_model_providers`, copies base URL/key/model slug into a `LocalEndpointConfig`, routes user queries, tool results, and passive suggestions locally, and **blocks** rather than forwards every other request. — [local_route.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/ai/agent/api/local_route.rs)
- The 1,720-line adapter is a protobuf compatibility layer inside the client: it reconstructs transcripts, exposes built-in and MCP tools, converts local calls into Warp `ToolCall` messages, and maps local engine events back to the existing `ResponseEvent` stream, so existing permission/execution code remains authoritative. — [local_adapter.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/ai/agent/api/local_adapter.rs); [implementation commit](https://github.com/man-brain/warp/commit/5c98eab3e73e54b22e38d218e2ac7966cb1f322c)
- Its fully-local commit enables `skip_login` and passive suggestions through the multi-agent path by default, hides built-in hosted models, makes telemetry no-op, and adds early errors to shared GraphQL/REST/agent-event/server-time/version routes. The commit reports a `strace` run with zero Internet socket connects. — [fully-local commit and diff](https://github.com/man-brain/warp/commit/92b7a7f9ddc531a7030d2bc450d708be2c148507)
- `skip_login` causes shared `AuthState::initialize` to install `User::test()` and test credentials; it also deliberately makes authenticated client requests fail. This is a compile-time synthetic identity, not a fake local account service. — [auth_state.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_server_auth/src/auth_state.rs); [session.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_server_client/src/auth/session.rs)
- Custom endpoint metadata is modeled separately from secrets: definitions are suitable for `settings.toml`, while custom endpoint keys are read/written through Warp's secure-storage abstraction under `AiCustomEndpointKeys`. The URL validator was changed to permit local/private endpoints. — [api_keys.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/ai/src/api_keys.rs); [local/private endpoint commit](https://github.com/man-brain/warp/commit/44559284f65d65983bfca3077cfac1de3652722d)

#### zerx-lab/zap
- Zap's README claims no mandatory account/cloud and supports generic OpenAI-compatible endpoints plus native OpenAI, Anthropic, Gemini, DeepSeek, and Ollama protocols. The code confirms this is not only documentation: `ResponseStream::new` resolves a `byop:` model, calls `generate_byop_output`, and otherwise produces a “BYOP required” stream instead of falling back to Warp inference. — [README](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/README.md); [response_stream.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/blocklist/controller/response_stream.rs)
- Zap's `chat_stream.rs` uses `genai` streaming adapters, explicitly maps five protocol types (`OpenAI`, OpenAI Responses, Gemini, Anthropic, Ollama), reconstructs multi-turn assistant/tool-result messages, streams text/reasoning, and emits Warp protobuf tool calls so the inherited controller performs permission prompts, execution, result persistence, and continuation. — [chat_stream.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/agent_providers/chat_stream.rs)
- Zap replaces upstream auth with a local facade whose `AuthState` always contains `User::test()`, whose `is_logged_in()` always returns true, and whose login views are empty stubs. This is broader and more invasive than man-brain's existing feature-based synthetic identity. — [auth/mod.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/auth/mod.rs)
- Provider names, endpoints, headers, and models live in settings, while `AgentProviderSecrets` serializes the provider-id-to-key map into OS secure storage. Empty keys are supported for unauthenticated local servers such as Ollama. — [agent_providers/mod.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/agent_providers/mod.rs); [secrets.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/agent_providers/secrets.rs)

#### rustcor-foundry/loom
- Loom intercepts local, subprocess/CLI, and native BYOK models **before** the inherited Warp server call. A selected local model therefore completes without Warp services; an unclaimed model can still fall through to the hosted server because Loom intentionally retains explicit cloud escalation. — [api/impl.rs](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/impl.rs)
- Its local dispatcher recognizes `ollama:`, `llama.cpp:`, `local:`, and `hermes-agent:` ownership, normalizes endpoints, accepts settings or environment overrides, POSTs `/chat/completions`, and does not hijack `byop:` or CLI-owned models. — [local_llm.rs](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/local_llm.rs)
- Loom's local tool bridge is the broadest inspected implementation: its schemas and converters cover shell and long-running shell control, file read/search/glob/diff, MCP resources/tools, skills, clarification, conversation fetch, documents, code review/project initialization, orchestration, and gated computer use. It converts provider calls into the same Warp protobuf client actions used by inherited approval/execution paths. — [local_llm.rs tool schemas and conversion](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/local_llm.rs); [Local AI documentation](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/docs/features/local-ai.md)
- Loom explicitly supports account-free local AI, BYOK, and authenticated CLI backends, while hosted services remain account-backed. The GUI onboarding includes “Continue without account”; hosted account support is separately feature-gated. — [account-free-ai.md](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/docs/features/account-free-ai.md); [login_slide.rs](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/auth/login_slide.rs); [auth/mod.rs](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/auth/mod.rs)
- Loom provider BYOK keys use Warp's secure storage, but the optional Local AI bearer key is documented as part of the local `[local_ai]` settings block. For our server, keeping the provider key in the server process environment is safer and simpler than copying Loom's local-key setting. — [ApiKeyManager secure storage](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/crates/ai/src/api_keys.rs); [local-ai settings](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/docs/features/local-ai.md); [our server README](file:///C:/Users/haita/warp/crates/warp_local_server/README.md)

### Inferences
- **Best source for isolation/auth mechanics:** man-brain is nearest to our 2026-09-30 checkout and uses upstream abstractions rather than deleting auth types. Its `skip_login` + explicit Warp-API deny pattern is lower-risk to borrow than Zap's wholesale authentication facade replacement. — [man-brain fork point and local commits](https://github.com/man-brain/warp/compare/3ec493c1401faf6552004988c2e22db22422815e...2f7576e71081118939fbd4c66aa38fd25277eecd)
- **Best source for provider breadth and advanced tool parity:** Zap and Loom contain much more adapter behavior, but transplanting it would duplicate our already-built Warp-Protobuf compatibility server and greatly expand client-side scope. — [Zap chat adapter](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/agent_providers/chat_stream.rs); [Loom local adapter](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/local_llm.rs); [our server protocol description](file:///C:/Users/haita/warp/crates/warp_local_server/README.md)
- Man-brain's local loop is genuinely serverless, Zap is local/BYOP-only, and Loom is local-first with an intentional hosted fallback. “No Warp inference for a selected local model” is verified for all three; “no possible Warp network traffic anywhere” is only an explicit invariant in man-brain and Zap. — [man-brain hard route guard](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/ai/agent/api/local_route.rs); [Zap response dispatch](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/blocklist/controller/response_stream.rs); [Loom fallback chain](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/impl.rs)

### Gaps
- No independent end-to-end or security audit was found for these forks; implementation claims were verified against source, but release reliability and whether every auxiliary feature avoids hosted traffic were not executed locally.
- Zap and Loom are large divergent forks. This review did not enumerate every deleted/stubbed cloud call or every feature that may still issue non-inference network traffic.

## Do any support the headless Warp TUI rather than only GUI?

### Takeaway
Only `man-brain/warp` contains the modern `crates/warp_tui` and, by Cargo feature unification, its default `skip_login` feature gives the TUI a synthetic validated identity and lets it proceed immediately. Zap and Loom do not contain `crates/warp_tui`; their account-free UI and provider configuration are GUI implementations and are not direct solutions for the headless TUI.

### Cited Findings
- Man-brain contains the same headless `warp_tui` crate and TUI login model as current upstream. The TUI dependency on `warp` does not disable default features, while the fork adds `skip_login` to the app crate's default feature set. — [warp_tui/Cargo.toml](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_tui/Cargo.toml); [app/Cargo.toml](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/Cargo.toml)
- The TUI decides its initial phase by checking for a logged-in user with a validated user ID. Under `skip_login`, `AuthState::initialize` supplies `User::test()` and test credentials, so `initial_login_phase` becomes `LoggedIn`; `session.rs` then creates the first terminal session immediately. — [app/src/tui/mod.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/tui/mod.rs); [AuthState skip-login path](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_server_auth/src/auth_state.rs); [TUI session initialization](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_tui/src/session.rs)
- Man-brain did not build a separate TUI provider UI; it benefits from shared app models. Its TUI already exposes custom endpoint status and key editing through `ApiKeyManager`, and its shared agent API route is used by both GUI and TUI. — [api_keys_menu.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/crates/warp_tui/src/api_keys_menu.rs); [shared api/impl.rs](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/ai/agent/api/impl.rs)
- Zap's checked tree has no `crates/warp_tui`; its provider setup lives in pixel/GPU Settings widgets and its agent stream is wired through the GUI blocklist controller. — [Zap crates tree](https://github.com/zerx-lab/zap/tree/8954864e335187aecb2b2319050adc8c4da256df/crates); [agent_providers_widget.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/settings_view/agent_providers_widget.rs); [response_stream.rs](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/blocklist/controller/response_stream.rs)
- Loom's checked tree likewise has no `crates/warp_tui`; its account-free controls are GUI onboarding/settings code. — [Loom crates tree](https://github.com/rustcor-foundry/loom/tree/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/crates); [login_slide.rs](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/auth/login_slide.rs); [AI settings page](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/settings_view/ai_page.rs)

### Inferences
- The earlier conclusion that man-brain's TUI still requires device login is incorrect for its current `local-agent` branch: the TUI source retains a login-gated state machine, but the fork's default `skip_login` feature makes its initial runtime state logged in. — [default feature change](https://github.com/man-brain/warp/commit/92b7a7f9ddc531a7030d2bc450d708be2c148507); [TUI initial-login check](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/tui/mod.rs)
- Zap and Loom remain valuable design references for GUI forks, provider protocol breadth, prompts, and tool conversion, but importing their account-free flow does not remove our TUI's `TuiLoginModel` gate without additional TUI-specific work. — [current upstream TUI login model](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/app/src/tui/mod.rs); [current upstream TUI root](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_tui/src/root_view.rs)

### Gaps
- I did not build and interactively launch man-brain's TUI, so its compile-time feature behavior is established from Cargo feature unification and source rather than a recorded runtime session.
- Neither Zap nor Loom documents a separate unreleased TUI branch; only the inspected public default heads were evaluated.

## What is the smallest robust integration pattern for our current server and TUI?

### Takeaway
Keep inference in `warp_local_server` and make a narrowly scoped **TUI local-backend mode**: a dedicated local inference URL, an explicit no-auth/no-ambient-header transport branch, and a synthetic/local TUI identity that bypasses only the login gate. Do not redirect the global Warp server root and do not transplant a second client-side agent loop.

### Cited Findings
- Our server already speaks exactly the inherited client protocol at `POST /ai/multi-agent`: Protobuf request in, URL-safe-base64 Protobuf `ResponseEvent`s over SSE out. It performs OpenAI-compatible provider translation while tool execution stays in the client permission path. — [warp_local_server README](file:///C:/Users/haita/warp/crates/warp_local_server/README.md); [server router](file:///C:/Users/haita/warp/crates/warp_local_server/src/lib.rs)
- Current `warp_multi_agent_client::generate_multi_agent_output` always calls `get_or_refresh_access_token`, derives the URL from global `ChannelState::server_root_url`, and resolves ambient headers before opening SSE. Therefore setting only `SERVER_ROOT_URL` is neither a login bypass nor an inference-only redirect. — [current multi-agent client](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_multi_agent_client/src/lib.rs)
- Global server-root overrides affect many unrelated account, GraphQL, update, sharing, auth, and cloud routes; our compatibility server intentionally implements only `/health` and `/ai/multi-agent`. — [ChannelState](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_core/src/channel/state.rs); [local server routes](file:///C:/Users/haita/warp/crates/warp_local_server/src/lib.rs); [integration-status warning](file:///C:/Users/haita/warp/crates/warp_local_server/README.md)
- Current upstream already has the useful identity primitive: `skip_login` installs a synthetic validated user, but the same feature intentionally causes authenticated requests to fail. That is compatible with a new local transport branch only if the branch skips authentication and ambient-header resolution altogether. — [current AuthState](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_server_auth/src/auth_state.rs); [current AuthSession](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_server_client/src/auth/session.rs)
- Man-brain demonstrates that a synthetic identity is sufficient for the shared TUI login state, and that unsupported cloud traffic should be blocked loudly/no-op'd rather than sent to an incomplete local service. — [fully-local commit](https://github.com/man-brain/warp/commit/92b7a7f9ddc531a7030d2bc450d708be2c148507); [TUI login model](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/tui/mod.rs)
- The TUI already has custom endpoint/key menus backed by shared settings and secure storage, so model/endpoint configuration can remain shared. Our server also allows a server-startup model override and prefers `DEEPSEEK_API_KEY` from the server environment, meaning the first integration need not add a new TUI secret store. — [current TUI API-key menu](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_tui/src/api_keys_menu.rs); [server configuration](file:///C:/Users/haita/warp/crates/warp_local_server/README.md)

### Inferences
- **Recommended minimal architecture:**
  1. Add an explicit TUI local-backend option (CLI flag and/or narrowly named environment variable such as `WARP_LOCAL_AGENT_URL`) rather than reusing `SERVER_ROOT_URL`. Parse and validate it as loopback HTTP unless an explicit future security design allows more. — [server loopback policy](file:///C:/Users/haita/warp/crates/warp_local_server/src/main.rs); [global override behavior](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/app/src/lib.rs)
  2. Thread that option into the multi-agent transport. Add a local variant/function which POSTs the same protobuf to `{local_url}/ai/multi-agent`, skips access-token, ambient-header, and team-header work, then reuses the existing SSE base64/protobuf decoder and cancellation semantics. Avoid conditionals scattered through `ServerApi`. — [current single transport seam](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_multi_agent_client/src/lib.rs)
  3. In this explicit mode, initialize a local validated identity for TUI startup (the existing `skip_login` machinery is the smallest proven approach) so `TuiLoginModel` starts `LoggedIn`. Scope feature activation to the local TUI build/mode rather than making every app build skip login. — [skip-login implementation](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/warp_server_auth/src/auth_state.rs); [TUI gate](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/app/src/tui/mod.rs)
  4. Suppress or locally stub only the startup/account side effects the TUI actually triggers (telemetry, user/workspace refresh, version checks, etc.); do not point them at the compatibility server. A single local-mode cloud-access policy/guard, modeled on man-brain's `warp_api_disabled`, is easier to audit than endpoint-by-endpoint fake responses. — [man-brain ServerApi guard](https://github.com/man-brain/warp/commit/92b7a7f9ddc531a7030d2bc450d708be2c148507)
  5. Reuse current local custom endpoint model definitions if available; otherwise inject one deterministic local model choice for local mode so startup never depends on Warp's model-catalog GraphQL response. Keep the actual provider key in `warp_local_server`'s environment and let `--model` select the provider model. — [current custom endpoint manager](https://github.com/warpdotdev/warp/blob/7cef787ea0e14073c907e7628ddb8d1a720222b5/crates/ai/src/api_keys.rs); [server key/model precedence](file:///C:/Users/haita/warp/crates/warp_local_server/README.md)
- This pattern preserves our server's tested wire adapter and the client's existing permissions/history/tool loop. Copying man-brain's 3,000+ line client adapter, Zap's much larger provider controller, or Loom's provider stack would create two inference implementations and make behavior drift likely. — [man-brain adapter commit](https://github.com/man-brain/warp/commit/5c98eab3e73e54b22e38d218e2ac7966cb1f322c); [Zap chat stream](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/agent_providers/chat_stream.rs); [Loom local stack](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/local_llm.rs)
- The best pieces to borrow are therefore **mechanical, not architectural wholesale**: man-brain's local identity/cloud deny posture; Zap/Loom's principle of converting model calls into inherited client tool actions; and Loom's strict model-owner routing to prevent a local mode from accidentally hijacking unrelated CLI/BYOK models. — [man-brain route guard](https://github.com/man-brain/warp/blob/2f7576e71081118939fbd4c66aa38fd25277eecd/app/src/ai/agent/api/local_route.rs); [Zap controller stream](https://github.com/zerx-lab/zap/blob/8954864e335187aecb2b2319050adc8c4da256df/app/src/ai/blocklist/controller/response_stream.rs); [Loom ownership guard](https://github.com/rustcor-foundry/loom/blob/8d7e9d71cf82511a64f2afe722ac4b6e0de72bc9/app/src/ai/agent/api/local_llm.rs)

### Gaps
- The exact minimum set of TUI startup cloud calls to suppress must be established by launching an instrumented local-mode build; source inspection identifies the architectural risk but not a complete runtime call inventory.
